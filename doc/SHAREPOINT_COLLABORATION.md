# OneDrive and SharePoint collaboration

ShareMap Desktop adds automatic saving, shared editing and native OneDrive
sharing to draw.io Desktop. It works with any `.drawio` file in a registered
Windows OneDrive or SharePoint sync folder. No company, tenant, map name or map
path is built into the app.

## Everyday use

Open a map from your synced folder. AutoSave starts automatically. Edit normally;
the fork merges other users' changes as OneDrive delivers them. Recent editor
avatars and selection outlines use the same sync route. No new account, app
registration, link setup or separate collaboration server is required.

**Share** opens OneDrive's existing sharing window for the containing folder,
including the map and its edit records. Review the folder shown before granting
access. Everyone editing needs this fork and Edit access to that folder.
SharePoint controls permissions. The **…** menu includes Manage access and Copy
link for people with access; copying that link does not grant new permissions.

**AutoSave On/Off** controls automatic saving and merging. With it off, the normal
Save command still saves and synchronizes. Save As creates an independent copy;
reopening that copy from a synced folder starts a separate shared session.

Unsynced diagrams retain draw.io's normal behavior. Collaboration can also be
enabled manually from the details dialog for other filesystem sync providers.
Native sharing requires Windows OneDrive's English Share/Manage access shell
commands. The app's settings and instance lock are separate from stock draw.io;
its file associations are unchanged and upstream automatic updates are disabled.

## Storage and recovery

Keep `Map.drawio.collab` beside `Map.drawio`; OneDrive must sync both.

- The immutable manifest contains the starting diagram, room ID and original
  file hash. Automatically enabled cloud maps also keep original file bytes in
  `original.json` inside that folder.
- Individually named immutable edit records contain draw.io patches, authors,
  Lamport clocks and causal parents. Independent property edits merge. Concurrent
  changes to the same property follow Lamport order with a UUID tie-break; both
  original records remain available for recovery.
- Hash records identify snapshots generated by this fork. The `.drawio` file is
  a conventional view/export; the edit journal is authoritative for shared use.
- Recent editor presence is optional, expires after 90 seconds and is separate
  from durable content. It includes account display names and selected cell IDs.

Reopening replays the journal. Missing causal parents wait for download. Changed
manifests, corrupt/missing records or unrecognized external file edits stop
snapshot writes rather than silently replacing someone else's work. Use this
fork for editing shared maps; stock draw.io cannot publish into the journal.

## Limits

This is eventual collaboration through OneDrive, **not Excel's Microsoft 365
co-authoring service**. There is no relay server or extraction of Microsoft
access tokens. OneDrive controls delivery; remote edits, presence and selection
outlines are not guaranteed to be instant. The header says **Saved locally**;
OneDrive provides the authoritative cloud upload status.

Let the first user's new journal finish syncing before opening a previously
unshared map on another computer. Simultaneous first-time initialization while
disconnected can create conflicting manifests; the app stops instead of mixing
rooms. A new computer must finish downloading earlier records before editing.

Current bounds are 16 MiB per diagram, 4 MiB per edit, 10,000 edits and 128 MiB
total journal. Save a new independent copy to start fresh. Automatic history
compaction and a full revision-history browser are not implemented. Presence
may lag or disappear with delayed sync or computer clock differences.

Tests use two isolated editor replicas with simulated asynchronous file delivery,
including concurrent edits, undo, offline reconnection, AutoSave control, recent
editor presence and reopening. A live multi-user Microsoft 365 deployment still
needs verification with those users' OneDrive clients.

## Build

Use Node 22.12+ and a recursive checkout:

```sh
npm ci
npm test
npm run test:shared-ui
npm run build:sharemap
```

If npm skips Electron's install script, run
`node node_modules/electron/install.js` before UI testing/building. The portable
Windows x64 build is unsigned.

Microsoft documents the underlying services in
[How sync works](https://learn.microsoft.com/en-us/sharepoint/sync-process) and
[Sharing with OneDrive](https://support.microsoft.com/en-us/onedrive/share-files-and-folders-in-microsoft-onedrive).
Registered sync-root mappings are read only for best-effort folder discovery.
